| 2026-08-24 | Ran a doubt-driven-development review cycle on the first draft of `docs/architecture.md`/`docs/setup.md` before merging; corrected three false claims it found | The first draft was synthesised from the 2026-08-22 audit and never independently re-checked against live repo state before publishing, despite claiming "as of 2026-08-24" currency. | 2026-08-24 | Ran a 2nd doubt-driven-development cycle on the corrected docs; found smaller but real errors introduced by the 1st correction itself | Most of the 1st correction's new precise claims (426/745 line counts, 62/15 test split, verbatim `main.tf` quote, 381-test count) verified exactly. | 2026-08-24 | Ran a 3rd doubt-driven-development cycle, paired: a full fresh review by one model, then every one of its findings independently cross-verified by a second, different model against the repos directly (not by re-reviewing from scratch) | Returns were not diminishing this round — this was the largest cycle yet, 13 material findings plus 6 minor, nearly all independently confirmed. Two stood out as a new failure class: veil-observatory's signature verification was called "a structural stub" and the receipt schema "never validated" — both false. A real HMAC verifier exists (`adapters/verification.py`), and a cross-repo schema reconciliation was ratified 2026-08-23, the day *before* this doc's stated date. In both cases this document had faithfully copied a claim from the component repo's *own* stale self-description (`correlation/correlator.py`, `ADR-0016` still assert the old stub posture) rather than reading the code. Also fixed: an elided verbatim quote that dropped load-bearing words ("not-yet-scoped", "zero-`String`, non-raw-capable"); a citation link that pointed at this repo itself instead of an external source; a section referencing "the two calls above" that were actually below it; the telemetry subsystem described as one file when it's ten (2,743 lines, mid-flight per its own latest commit message); veil-custodian's Postgres test count undercounted again (15→19, 2 files→3, and the default `cargo test` invocation never reaches the third file at all — confirmed by directly running it); veil-demo's dependency pin described as "wired and running" without noting it's 3 weeks stale against veil-proxy's HEAD and pins six crates, not one; a trust-boundary claim that telemetry carries a raw "actor id," contradicting the device-pseudonym rule two lines later — it's actually a keyed-HMAC pseudonym, and is not currently derived from the OS username as an early draft of this fix claimed (verified directly: it's a free-typed CLI argument, and OS username is only a hypothetical future case named in the source's own comment); and a third broken setup.md command (`vg` needs `-p vg-cli` and a `PATH` export neither round 1 nor round 2 caught). Two of nineteen cross-verified findings came back "partially confirmed" rather than clean — verified directly rather than taken on either model's word alone. |
| 2026-08-24 | Wrote `docs/interactive-plan.md`: public dashboard + local orchestration + interactive docs artifact, phased, public launch gated on explicit human `public_release` approval | Produced via a 3-stage review chain (Fable design → Codex critique against live repo state → Opus reconciliation with independent verification). Phasing was restructured around that dependency: nothing public-facing before this merge and a human decision on whether the security-gap content this document documents (veil-custodian's full route/authz surface, self-asserted demask auth, veil-observatory's unkeyed hash chain) should be public. Also killed a proposed `integration-status.yaml` mirror file after finding this repo's own `risk-register.yaml`/`risks.md` had already drifted (1 risk vs. 5) — same-PR discipline alone isn't sufficient; the collector should parse `architecture.md`'s table directly instead of maintaining a second source. |
| 2026-08-29 | Closed seam #1's crypto contract as `veil.edge_event.v1`, not `veil.receipt.v2` — a deliberate scope narrowing, decided and implemented in one session | `Receipt`/`veil.receipt.v2` needs an aggregator veil-proxy has not built (`aggregator.rs` remains an explicit skeleton; `TryFrom<&AuditEvent>` still rejects `Scan`/`PolicyDecision` with `RequiresAggregation`). `EdgeEvent` is already producible in production today from `DemaskRequest`/`DemaskDecision`/recognized `Block` reasons, so it was chosen as the realistic weekend-scoped target instead of waiting on unscoped aggregator work. Every field reachable from the serialized `EdgeEvent`/`Envelope`/`Integrity` types was individually audited against this doc's own "never crosses the boundary unconditionally" rule before implementation — closed enums, fixed-width hashes, and bounded tokens only, no raw-string escape hatch — and a regression test locks in that the raw actor identifier never appears in the wire payload. Built on both sides (veil-proxy: canonical JSON + HMAC-SHA256 signing; veil-observatory: schema, generalized verifier, loopback HTTP receiver) and cross-verified against one shared golden vector, independently re-run in this session rather than taken on either builder's self-report. See `docs/architecture.md`'s Integration Status update and `docs/next-actions.md` for exactly what's still not wired (the HTTP client, the audit-sink hook, and merging/pushing either branch). |
| 2026-08-29 | Fixed a real secret leak in veil-foundations (a sibling repo) found incidentally by a publishability review this session, before any visibility decision on that repo | `veil-foundations/docs/{decisions,implementation-plan,infra-lab-reuse}.md` named a real AWS account ID and a private internal stealth project's codename and repo-relative file path, in the course of documenting a shared Terraform-state-bucket investigation.
